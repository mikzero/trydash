Your TryCloudflare quick tunnels,
in one dashboard.

Expose a dev service or a folder in one click, see every request that comes in, and follow all your tunnels and their logs in one place. A single executable for Linux, macOS and Windows: nothing to install besides cloudflared.

Download trydash Code on GitHub

Executables for 5 systems, verifiable with SHA256SUMS.

Why

cloudflared tunnel --url http://localhost:3000 is great, but with two or three services running you end up with several terminals to watch, URLs to copy around and logs that are hard to read. trydash starts and manages quick tunnels for you.

New in 2.0

Request inspector

Every request through the tunnel, with headers and body. Replay it, edit it first, or copy it as curl: made for webhooks.

Publish a folder

Type ~/site/dist instead of a port: trydash serves the folder itself, no local server needed. Hidden files stay out.

Command line

trydash 3000 opens the tunnel and the dashboard in your browser, ready for a package.json script.

Expiry and saved tunnels

A tunnel can stop by itself after 30 minutes or a day. Your tunnels come back, stopped, the next time you start trydash.

QR code and notifications

Scan the URL with your phone. Get a browser notification when a tunnel is ready or your server stops answering.

Safer by default

An access token at every start, no framing by other sites, tunnels that really stop. The interface speaks English and Italian.

Features

Many tunnels at once

Each with its status, URL and error count. To create one, just type the port: 3000 becomes http://127.0.0.1:3000.

Readable logs

Colored levels, filters, highlighted search, infinite scrolling and a “follow the tail” mode.

Email access

Limit a tunnel to specific addresses or whole domains (*@company.com). A list pasted from Outlook works too.

Live traffic

Requests in flight against the 200 limit, totals, errors, connections and a chart of the last 5 minutes.

Origin options

Host header, unverified TLS for self-signed certificates, HTTP/2 origin. A preview shows the equivalent cloudflared command.

Helpful warnings

It tells you when your origin isn’t responding, when you get close to the request limit and when a restart will change the URL.

Plus: the development servers running on your computer suggested in the form, a Hello World test without a local server, stopped tunnels you can still read, light and dark themes, a mobile layout and keyboard shortcuts. The interface follows your browser, in English or Italian.

Download

  1. Install cloudflared

    It must be on your PATH. Follow Cloudflare’s guide; if it’s missing, trydash shows you the commands for your system.

  2. Download the executable

    SystemFile
    Linux x64trydash-2.0.0-linux-x64
    Linux ARM64trydash-2.0.0-linux-arm64
    macOS Apple Silicontrydash-2.0.0-darwin-arm64
    macOS Inteltrydash-2.0.0-darwin-x64
    Windows x64trydash-2.0.0-windows-x64.exe

    Check the file with SHA256SUMS: sha256sum -c SHA256SUMS --ignore-missing

  3. Run it

    chmod +x trydash-*-linux-x64     # Linux and macOS
./trydash-*-linux-x64            # or: ./trydash-*-linux-x64 3000

    The dashboard opens in your browser, with its access token. Type your service’s port, or a folder, and press Create; with 3000 after the command, the tunnel starts right away. Without a browser, open the address it prints, like http://127.0.0.1:8787/?token=…. On Windows, just run the .exe file.

    The binaries aren’t signed. On macOS, lift the Gatekeeper block with xattr -d com.apple.quarantine trydash-*; on Windows, if SmartScreen shows up, choose “More info” and then “Run anyway”.

Prefer to run from source? You need Bun ≥ 1.1: git clone https://github.com/mikzero/trydash.git && cd trydash && bun start.

Good to know about quick tunnels

  • the *.trycloudflare.com URL is random and changes on every start;
  • at most 200 concurrent requests per tunnel; beyond that the response is 429;
  • Server-Sent Events aren’t supported;
  • no uptime guarantee: for production you need a named Cloudflare Tunnel.

Security

  • the dashboard only listens on 127.0.0.1 and answers only with the token it prints at start-up;
  • other sites can’t control it or show it inside their pages;
  • the server stays on HTTP/1.1. The 2.0.0 binaries embed Bun 1.4.4, with the QPACK fix;
  • no accounts: logs and inspected requests stay in memory, saved tunnels keep only their settings;
  • a tunnel makes the service you expose public: protect it with email access or an expiry.
